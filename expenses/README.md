# expenses — анализ личных расходов по месяцам

Забирает операции из выгрузки банка, с биржи Bybit или из произвольного
REST API, разносит их по категориям и показывает, куда уходят деньги:
помесячная сводка, доля каждой категории, что изменилось к прошлому
месяцу, крупнейшие траты и регулярные списания вроде подписок.

Пакет самостоятельный: зависит только от `requests` и стандартной
библиотеки, к остальному репозиторию отношения не имеет.

## Быстрый старт

```bash
pip install -e .

expenses demo                      # отчёт на синтетических данных
expenses import выписка.csv        # загрузить выгрузку из банка
expenses report --months 6         # помесячная сводка
```

Без конфига всё работает на умолчаниях: валюта — шекель, операции
складываются в `data/expenses.jsonl`.

## Команды

| Команда | Что делает |
|---|---|
| `expenses import ФАЙЛ` | загружает CSV/TSV/JSON/JSONL, колонки распознаются сами |
| `expenses fetch --source bybit --months 6` | забирает операции с биржи |
| `expenses probe --source bybit` | проверяет доступ к API и показывает его поля |
| `expenses report` | помесячный отчёт: `--format text\|md\|csv\|json` |
| `expenses recurring` | подписки, аренда, страховки и во что они обходятся за год |
| `expenses unknown` | что не попало ни в одну категорию — список для донастройки |
| `expenses test-rule "ТЕКСТ"` | проверить, куда попадёт конкретная операция |
| `expenses stats` | что лежит в хранилище |

Глобальные опции идут **до** команды: `expenses --data мои.jsonl report`.

Период задаётся либо `--months N` (последние N месяцев, считая от самой
свежей операции в данных), либо парой `--since` / `--until`.

## Подключение Bybit

Ключу нужны **только права на чтение**. Торговые права и права на перевод
средств анализатору не требуются — не выдавайте их. Если ключ где-то
засветился (скриншот, переписка), удалите его в Bybit → API Management и
выпустите новый.

1. Скопируйте `expenses.example.toml` в `expenses.toml`, включите
   `[sources.bybit] enabled = true`.
2. Положите ключи в `.env` рядом — в git этот файл не попадает:

   ```
   BYBIT_API_KEY=...
   BYBIT_API_SECRET=...
   ```

3. `expenses probe --source bybit` — проверит подпись, права и покажет,
   сколько записей доступно по каждой ручке.
4. `expenses fetch --source bybit --months 6`.

Запросы подписываются по схеме V5 (HMAC-SHA256 от
`timestamp + api_key + recv_window + query`), страницы берутся курсором,
длинный период автоматически режется на окна, которые Bybit разрешает.

### Что именно считается расходом

Биржа — не банк, и «расход» здесь другой. Забираются вводы
(`/v5/asset/deposit/query-record`), выводы
(`/v5/asset/withdraw/query-record`) и журнал операций единого счёта
(`/v5/account/transaction-log`), и раскладываются так:

| Запись | Категория | Направление |
|---|---|---|
| ввод средств | Пополнение биржи | приход |
| вывод средств | Вывод с биржи | расход |
| комиссия сети за вывод | Комиссии биржи | расход |
| торговая комиссия | Комиссии биржи | расход |
| фандинг | Фандинг | расход или приход по знаку |
| проценты по займу | Проценты по займу | расход |
| сделка | Сделки | по умолчанию не попадает в отчёт |
| перевод между своими счетами | Переводы между счетами | по умолчанию не попадает |

Сделка деньги не тратит — она меняет одну монету на другую, поэтому из
неё берётся только комиссия. Включается через `include_trades = true`,
переводы — через `include_transfers = true`.

Суммы приходят в монетах, и монета становится валютой операции. Чтобы
увидеть их в шекелях, задайте курсы в `[fx].rates`:

```toml
[fx]
rates = { USDT = 3.70, BTC = 400000 }
```

## Подключение своего банка по API

Для API с обычной авторизацией по токену отдельный модуль не нужен —
всё описывается конфигом в `[sources.rest]`: `base_url`, авторизация
(`bearer` / `header` / `query` / `basic`), параметры периода, пагинация
(по номеру страницы, смещению или курсору) и имена полей, включая
вложенные пути (`payment.sum`) и списки кандидатов (`["sum", "amount"]`).

`expenses probe --source rest` покажет первую страницу ответа и имена
полей, чтобы было что переносить в `[sources.rest.fields]`.

## Категории

Встроенный набор правил покрывает израильские сети и мировые сервисы —
`שופרסל`, Rami Levy, Aroma, Wolt, Paz, Rav Kav, Cellcom, Maccabi, Super
Pharm, Netflix, El Al и так далее; ищет и на иврите, и на латинице, и на
русском.

Свои правила добавляются в `expenses.toml` и всегда приоритетнее
встроенных:

```toml
[[rules]]
category = "Помощь родителям"
patterns = ["перевод маме", "HELP MOM"]

[[rules]]
category = "Крупные переводы"
patterns = ["העברה"]
min_amount = 5000
direction = "expense"
```

Рабочий цикл — `expenses unknown`, дописать пару правил, повторить, пока
список не опустеет.

## Как это устроено

```
sources/  →  models.Transaction  →  categories  →  analyze  →  report
```

Источник отвечает только за получение сырых записей и маппинг полей.
Дальше всё работает с одной моделью и про формат исходных данных не
знает, поэтому новый банк подключается описанием полей, а не новым кодом.

Операции хранятся в JSONL — по одной на строку, файл читается глазами.
Дубли отсеиваются по id операции, а если источник его не даёт — по
связке «дата + сумма + описание», так что повторный импорт той же
выписки расходы не удваивает.

## Что стоит знать

- Текущий месяц в отчёте неполный, и он участвует в строке «в среднем за
  месяц» — на середине месяца среднее занижено. Помесячная таблица рядом,
  так что перекос видно.
- Регулярным считается списание, которое встречается в 3+ месяцах и не
  скачет по сумме больше чем на 25% (настраивается в `[categories]`).
  Считаются месячные суммы, а не отдельные операции.
- Валюты пересчитываются по фиксированным курсам из `[fx].rates`. Если
  курса нет, сумма идёт в отчёт как есть, и в лог пишется предупреждение —
  молча складывать шекели с долларами нельзя.
- Bybit — источник про движение средств, а не про повседневные траты.
  Картина «куда уходят деньги» получается из банковской выписки; биржа
  добавляет к ней комиссии, фандинг и выводы. Оба источника пишутся в
  одно хранилище и попадают в один отчёт.
- Курс монеты в `[fx].rates` фиксированный, историю курсов программа не
  знает. Для стейблкоинов это точно, для BTC — оценка по сегодняшнему
  курсу, а не по курсу на дату операции.
