# landtender — ежедневный трекер земельных тендеров Израиля

Программа раз в сутки обходит государственные порталы Израиля и частную
площадку Yad2, собирает земельные лоты, считает **стоимость земли** и
**количество единиц строений**, делит выдачу по порогу в **1 000 000 $** и
присылает сводку в Telegram — только то, чего не было вчера.

```
🇮🇱 Земельные тендеры Израиля — дневная сводка
Дата: 2026-07-27
Порог: $1.00 млн · курс USD/ILS: 3.6412 (boi)
Просмотрено записей: 412 · новых: 9 · изменившихся: 3

🔥 Дороже порога — 4 лот(ов), единиц строений: 96
• חי/142/2025 · חיפה, נווה שאנן
  💰 $5.08 млн (18 500 000 ₪) · min
  🏘 единиц: 60 · 📐 4 200 м² · за единицу $84 679
  מגורים · до 2026-09-15
```

## Что считается

| Величина | Как получается |
|---|---|
| Стоимость земли | Цена сделки (`SchumZchiya`) → минимальная цена (`MechirSaf`) → оценка шамая (`mechirShuma`) → цена продавца. Приоритет настраивается. |
| Сроки | `PirsumDate` — публикация, `PtichaDate` — открытие приёма заявок, `SgiraDate` — закрытие. До открытия цены у тендера нет, и это видно в строке. |
| Стоимость в долларах | Официальный представительный курс Банка Израиля, кеш на 12 часов, откат на курс из конфига. |
| Количество единиц строений | Поле `YechidotDiur` (יחידות דיור) участка → то же поле тендера → число из текста (`12 יח"ד`) → 1 для участков под индивидуальный дом. |
| Цена за единицу / за м² | Стоимость в долларах, делённая на единицы и на площадь. |
| Группа | `premium` — от порога и выше, `standard` — ниже, `unknown` — цена неизвестна. Справочное поле: делить выдачу по нему или нет, решает `split_by_threshold`. |
| Вид работ | Пустой участок или площадка со строением: `pinui_binui` (расселение и застройка), `tama_38` (усиление здания), `demolition` (снос), `preservation` (здание под охраной), `urban_renewal`, `existing_structure`. |
| Назначение земли | `agriculture`, `residential`, `commerce`, `industry`, `public`, `tourism` — по назначению участка, примечанию и названию тендера. Непонятное остаётся пустым. |

Участки со старыми строениями попадают в сводку наравне с пустыми и
помечаются значком 🏚 с указанием площади существующей застройки. Признаки:
ивритские термины в названии, назначении или примечании тендера
(פינוי בינוי, התחדשות עירונית, תמ"א 38, הריסה, מבנה לשימור, מבנה ישן),
а также ненулевое поле площади застройки `ShetachBniya`.

### Сельхозземля

Вся сельскохозяйственная земля, выставленная на тендеры, попадает в сводку
наравне с городскими участками и помечается значком 🌾. Отдельная строка в
шапке показывает, сколько таких лотов и сколько это гектаров:

```
🌾 Сельхозземля: 3 лот(ов), всего 41.8 га
...
• מכרז חקלאי 151/2026 · בקעת בית שאן
  💰 $796 441 (2 900 000 ₪) · min
  🏘 единиц: — · 📐 145 000 м²
  🌾 сельхоз · חקלאות — מטעים · до 2026-11-05
```

Признаки — ивритские термины в назначении участка, примечании или названии
тендера: חקלאות, קרקע חקלאית, מטעים, מרעה, נחלה, משק עזר, חממות, לולים, רפת,
גד"ש, בית אריזה. Назначение участка важнее общего назначения тендера: если
миграш отмечен как сельхоз, лот считается сельхозным, даже когда тендер
подписан обобщённо. Названия кварталов вроде «נחלת יהודה» за наделы не
принимаются.

Дневная сводка по устройству показывает только новое, поэтому «вся
сельхозземля» — отдельная команда: она делает срез всей базы, а не одного
дня.

```bash
landtender farmland                # действующие тендеры, дорогие сверху
landtender farmland --all          # включая закрытые
landtender farmland --send         # отправить срез в Telegram
landtender farmland --out farm.csv # таблицей
```

Лоты, попавшие в базу до появления разбора назначения, доразбираются на лету —
стирать базу не нужно.

**Почему у сельхозлотов часто нет цены.** Разведка портала по тендеру
406/2025 (Иерусалим, назначение «חקלאות») показала:

```
"MechirSafMichraz": null,
"Tik": [{ "MechirSaf": null, "mechirShuma": 0, "Shetach": null }],
"PtichaDate": "2026-10-26",
"SgiraDate":  "2026-12-28",
"MessageDetails": { "messageText": "המכרז טרם נפתח להגשת הצעות" }
```

Тендер объявлен, но **приём заявок ещё не открыт** — до даты открытия портал
держит מחיר מינימום пустым. Программа это не скрывает и не выдумывает: в
строке пишется «цена будет с 2026-10-26» и окно подачи заявок целиком.

## Полезность лота и запас прочности

Пять показателей, каждый отвечает на отдельный вопрос. Все в шкале 0–100:

| Показатель | Вопрос | Вес |
|---|---|---|
| Цена против оценки | насколько минимум ниже рыночного уровня | 0.35 |
| Смена назначения | переводят ли участок под застройку и на какой стадии | 0.25 |
| Плотность застройки | сколько единиц жилья на дунам | 0.15 |
| Глубина рынка | на скольких сделках построена оценка | 0.15 |
| Срок подачи | успеть ли подготовить заявку с гарантией | 0.10 |

Неизвестный показатель **не заменяется нулём и не считается средним** — он
просто не входит в балл, а веса перенормируются. Рядом с баллом печатается,
сколько показателей из пяти удалось посчитать: `[84/4п]`.

### Почему срез по городу бывает пуст

Пустой срез называет шаг, на котором опустел: города нет в базе, цены нет
ни у одной записи, всё дороже порога. Это три разных ответа и три разных
следующих шага, а раньше на всех была одна фраза «под условия ничего не
подошло».

Так нашлась причина пустого Иерусалима: из 2364 действующих лотов на город
приходятся 213, и **ни у одной записи нет объявленной цены**. Это проекты
городского обновления и планы (номера вида `101-0502948`), а не торги —
цены у них не бывает по природе. Действующих земельных торгов с ценой в
Иерусалиме сейчас нет; это ответ, а не поломка.

### Минимальная цена — не рыночная

У действующего тендера рм"и цена в выдаче — это **מחיר מינימום**: порог, ниже
которого заявку не примут. Оценка же построена на `SchumZchiya` — суммах,
которые победители реально заплатили. Сравнивать одно с другим как «скидку к
рынку» нельзя: в первом полном прогоне «дешевле оценки более чем на 20%»
получили 127 лотов из 159 оценённых. Это не находки, а определение резервной
цены.

Поэтому в таблице стоит колонка **вид цены** (`мин.`, `сделка`, `шумá`,
`запрос`), а вердикт по лоту с резервной ценой звучит как «старт на N% ниже
оценки» и не получает 🟢. Зелёная отметка остаётся за ценами, сравнимыми с
оценкой по природе.

#### Надбавка торгов

Калибровка сделана. У закрытого тендера теперь хранятся **обе** цены:
`price_nis` — то, чем кончилось, `reserve_price_nis` — с чего начали. По
парам внутри одного тендера считается медианное отношение «цена сделки /
минимальная цена» — во сколько раз торги поднимают старт. Поправка на время
здесь не нужна: начало и конец торгов разделяют недели, а не годы, поэтому
надбавка не зависит ни от индекса ЦСБ, ни от регрессии.

Дальше стартовая цена действующего тендера умножается на надбавку, и с
оценкой сравнивается уже **ожидаемая цена сделки** — как в балле цены, так
и в вердикте. Зелёный кружок у лота с резервной ценой означает теперь, что
он остаётся дешевле оценки **после** надбавки, и в вердикте прямо написано,
какой: `🟢 −44% к оценке с надбавкой ×1.40`.

Чего надбавка требует. Пар «минимум → сделка» нужно не меньше тридцати
(`MIN_PREMIUM_DEALS`), а отношение вне границ 1–10 отбрасывается:
символическая минимальная цена характеризует опечатку, а не торги. Пока пар
не хватает, множитель не подставляется — подставить единицу значило бы молча
утверждать, что торги цену не поднимают. В этом случае всё работает как
раньше (балл у стартовых цен завышен), и сводка сама об этом предупреждает
строкой «⚠️ Надбавка торгов неизвестна».

Важно: колонка появилась только сейчас, поэтому у уже собранного архива она
пуста — детали тендеров портал отдаёт по запросу, а кеш отпечатков не даёт
забрать их повторно. Один раз архив нужно перезабрать:

```bash
landtender harvest --refresh --minutes 165
```

Заход накопительный и ограничен собственными часами, так что полный проход
займёт несколько запусков. `landtender harvest` печатает, сколько пар
набралось и на каком шаге теряются остальные.

### Что приходит в канал каждый день

Три вещи, и ровно в таком порядке:

1. **Сводка одним сообщением** (`landtender summary`) — что изменилось за
   сутки, сколько лотов с ценой и оценкой, сколько находок, чем кончились
   срезы, и пять предложений, которые стоит открыть первыми.
2. **Топ-10** — лучшее из накопленного по общему баллу.
3. **CSV со всей таблицей** — все предложения, все показатели.

Раньше сюда же уходило около ста тридцати сообщений листинга, и два
полезных тонули в ста двадцати восьми. Столько текста не читают: сводку
читает один человек с телефона утром, а по таблице считают — это разные
вещи, и мерить их одной формой нельзя. Поэтому `landtender all` по
умолчанию строк в сообщения больше не шлёт (`--full` вернёт прежнее
поведение, `--limit N` покажет первые N), сбор перестал слать свою
отдельную сводку новинок, а пустые срезы (`--skip-empty`) сворачиваются в
строку сводки вместо ежедневного сообщения ни о чём.

### Место у лотов без города

У 1240 лотов рм"и нет ни названия населённого пункта, ни кода ЦСБ, а без
места лот нельзя ни оценить, ни сравнить. Разбор показал, что чинить это
нечем: их тендеров нет в выдаче поиска портала — `без кода, тендер в выдаче
есть 0`. Один запрос закрывает 55 512 лотов из 56 752, остальное этим путём
недостижимо. Поэтому запрос делается **раз в сутки** на шаге сбора, а не
перед каждым показом, как было: пять одинаковых обращений по три минуты —
это пятнадцать минут работы ради данных, которые не менялись с первого раза.

### Полная выгрузка

`landtender all` показывает **всё, что есть в базе**, по строке на лот: сперва
названия показателей, затем значения через запятую. В отличие от топа здесь
ничего не отсеивается — лот без цены или без оценки остаётся в списке с
прочерками. Прочерк тоже сведение: он говорит, что портал цену ещё не
объявил, а не что лота нет.

Порядок неслучаен: сперва лоты, у которых есть и цена, и балл, потом
остальные. Сортировать одним баллом нельзя — часть показателей считается без
цены, и лот, о котором известен только срок подачи, набрал бы их полностью и
обошёл участок с честной оценкой.

Длинный список режется на страницы, и каждая начинается со своей строки
названий колонок: читающий двадцатое сообщение подряд не должен возвращаться
к первому, чтобы понять, что означает седьмое число. Полный список всегда
уходит ещё и CSV-файлом — по нему считают, а не читают.

### Сбор сравнимых сделок

```bash
landtender enrich               # добрать площади из кадастра govmap по всей базе
landtender city --city ירושלים --max-usd 1000000   # участки под жильё в городе
landtender farmland --max-usd 100000               # сельхозземля дешевле порога
landtender top                  # топ-10 предложений из базы по общему баллу
landtender top --send           # то же в Telegram
landtender top --why            # чего не хватило остальным, в разрезе источников
landtender summary              # сводка одним сообщением: что изменилось за сутки
landtender all                  # все предложения со всеми показателями (строки — в CSV)
landtender all --full           # то же строками в сообщениях (сотня с лишним)
landtender all --send --attach --out all.csv   # то же в Telegram, с CSV в приложении
landtender harvest              # порция архива закрытых торгов
landtender harvest --minutes 20 # заход покороче; по истечении срока
                                # собранное сохраняется, остальное — в следующий раз
```

Сбор **накопительный**: кеш отпечатков не даёт забирать одно и то же, и
каждый следующий запуск добирает новые тендеры. Порция по умолчанию
небольшая намеренно — портал отвечает по паре секунд на запрос, и большая
порция не укладывается в лимит времени задачи CI. Полный архив набирается
за несколько заходов.

**Запас прочности** — до какой суммы можно поднимать заявку:

```
затраты(ставка) = ставка·(1 + налог + прочие) + расходы на развитие
предельная ставка: затраты ≤ оценка / (1 + целевая доходность)
```

```
🎯 предельная ставка 3 390 000 ₪ (+17% к минимуму)
💼 ROI при выигрыше по минимуму: 32%
⚠️ минимальная цена уже выше предельной ставки
```

Никакой надбавки «за то, что участок скоро переведут под застройку» здесь
нет: сколько именно прибавит утверждение плана, данные не говорят, и такой
коэффициент был бы выдуман. Смена назначения остаётся отдельным
показателем, а не тайной добавкой к деньгам. Ставки налогов — в конфиге
`[bidding]`: они меняются законом, а не кодом.

Выведенные (не пришедшие напрямую) единицы помечаются знаком `≈`.
Неизвестные значения остаются пустыми — программа их не выдумывает.

## Установка

```bash
git clone https://github.com/vadimsheinberg-beep/usreal.git
cd usreal
pip install -e .          # или: pip install -r requirements.txt
cp landtender.example.toml landtender.toml
```

Требуется Python 3.11+ (используется stdlib-модуль `tomllib`).

## Подключение Telegram-канала

### Быстрый способ: мастер настройки

```bash
landtender setup
```

Мастер спросит токен и канал, проверит их, запишет `.env` с правами 600 и
пришлёт в канал демонстрационную сводку — сразу видно, как всё выглядит:

```
Настройка Telegram-канала для landtender.

Токен бота от @BotFather: 123456789:AAH...
  ✓ Бот @my_land_bot (Land Tenders)

Куда слать сводку. Бот должен быть администратором канала.
  • публичный канал — введите @имя_канала
  • приватный канал — введите ? , чтобы найти id по входящим сообщениям
Канал: @my_land_channel
  ✓ Канал: Земельные тендеры (id -1001234567890)

✓ Настройки записаны в .env (права 600)
✓ В канал отправлена демонстрационная сводка — проверьте, как она выглядит
```

Посмотреть демонстрацию, ничего не отправляя: `landtender demo --dry-run`.
Отправить её в канал ещё раз: `landtender demo`. Данные в ней вымышлены и
сообщение об этом предупреждает — с реальными тендерами не спутать.

### Вручную

1. Создайте бота у [@BotFather](https://t.me/BotFather) → получите токен.
2. Добавьте бота **администратором** вашего канала и напишите туда любое
   сообщение.
3. Положите токен в файл `.env` рядом с конфигом:

```bash
cp .env.example .env
$EDITOR .env          # вписать TELEGRAM_BOT_TOKEN
```

4. Укажите канал в `.env`. Если у него есть публичное имя — просто напишите
   его со знаком `@`, искать числовой id не нужно:

```bash
TELEGRAM_CHAT_ID=@my_land_channel
```

Для приватного канала нужен числовой id — его подскажет `--discover`
(предварительно напишите в канал любое сообщение):

```bash
landtender telegram-test --discover
#   -1001234567890   channel    Земельные тендеры
```

5. Проверьте всю цепочку — токен, доступ к каналу, отправку:

```bash
landtender telegram-test
# ✓ Токен принят: @my_land_bot (Land)
# ✓ Канал доступен: Земельные тендеры (id -1001234567890)
# ✓ Пробное сообщение отправлено
```

Вместо `.env` можно задать обычные переменные окружения
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — они приоритетнее файла, так это
и работает в GitHub Actions. Токен не хранится ни в конфиге, ни в git: в
`landtender.toml` стоит только ссылка `env:TELEGRAM_BOT_TOKEN`, а `.env`
внесён в `.gitignore`.

Кроме текстовой сводки в тот же канал уходит CSV со всеми новыми лотами
(`attach_csv = true` в секции `[telegram]`). Если файл не проходит — сводка
всё равно считается доставленной, и завтра лоты не придут повторно.

У приватных каналов `chat_id` отрицательный и начинается с `-100`. Если
`--discover` ничего не находит: боту уже назначен вебхук либо апдейты
вычитаны — тогда проще посмотреть id в
`https://api.telegram.org/bot<ТОКЕН>/getUpdates` вручную.

Самая частая причина ошибки `chat not found` или `bot is not a member` —
бот не добавлен в канал администратором. Права на публикацию сообщений
обязательны, остальные не нужны.

## Запуск

```bash
landtender setup                       # мастер настройки канала
landtender demo                        # прислать в канал пример сводки
landtender check                       # проверить доступность источников
landtender telegram-test               # проверить подключение канала
landtender run --dry-run               # прогон без отправки: сводка в консоль
landtender run                         # ежедневный запуск
landtender run --sources rmi_michrazim # только один источник
landtender export --format csv --tier premium --days 30
landtender farmland                    # вся сельхозземля из базы
landtender stats                       # состояние базы и последний запуск
```

Полезные флаги `run`: `--threshold-usd` (свой порог), `--full-refresh`
(перезабрать детали всех тендеров), `--no-notify`, `--export-csv/--export-json`.

Коды возврата: `0` — успех, `1` — упали все источники, `2` — ошибка конфигурации.

### Первый запуск

Первый прогон видит все лоты как новые, поэтому сводка будет большой, а
детали тендеров догружаются с паузой в секунду — это нормально и занимает
несколько минут. Разумно начать так:

```bash
landtender run --no-notify     # наполнить базу молча
landtender run                 # дальше приходит только новое
```

## Ежедневный запуск

### Установка на сервер одной командой

```bash
git clone -b claude/israel-land-tenders-tracker-sz1k6y \
  https://github.com/vadimsheinberg-beep/USREAL.git /opt/landtender
sudo bash /opt/landtender/deploy/install-landtender.sh
```

Скрипт ставит зависимости, создаёт системного пользователя `landtender`,
виртуальное окружение, конфиг, `/etc/landtender.env` (права 640) и включает
таймер на 09:00 со случайной задержкой до 15 минут. Повторный запуск
обновляет код и юниты, базу и токены не трогает. После установки останется
вписать токен и id канала в `/etc/landtender.env` — скрипт напечатает
остальные шаги.

Каталог `/opt/landtender` выбран намеренно: в `/opt/usreal` из этого же
репозитория живёт месячный отчёт по расходам (другая ветка) — в общем
каталоге две программы затирали бы код друг другу при обновлении.

```bash
systemctl list-timers landtender.timer          # когда следующий запуск
journalctl -u landtender.service -n 50          # что было в последний раз
systemctl start landtender.service              # запустить прямо сейчас
```

### cron

```cron
0 9 * * * cd /opt/landtender && /usr/bin/env TELEGRAM_BOT_TOKEN=... TELEGRAM_CHAT_ID=... \
          /opt/landtender/.venv/bin/landtender run >> /var/log/landtender.log 2>&1
```

### systemd вручную

Файлы `deploy/landtender.service` и `deploy/landtender.timer` — скопируйте в
`/etc/systemd/system/`, затем:

```bash
systemctl enable --now landtender.timer
```

### GitHub Actions

`.github/workflows/daily.yml` запускает трекер каждый день в 06:00 UTC.
Добавьте секреты репозитория `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
База между запусками сохраняется через `actions/cache`.

## Конфигурация

Все параметры и комментарии — в `landtender.example.toml`. Наиболее важные:

```toml
[general]
threshold_usd = 1_000_000     # порог деления на группы
settlements = []              # города; [] — вся страна
split_by_threshold = false    # false — не делить выдачу по цене
hide_expired = true           # прятать тендеры с истёкшим сроком подачи
rate_limit_delay = 1.0        # пауза между запросами; ниже 0.5 порталы дают 429

[valuation]
price_preference = ["final", "min", "appraisal", "asking"]
include_development_costs = false   # прибавлять ли הוצאות פיתוח к цене земли

[telegram]
send_standard_tier = true     # false — присылать только лоты дороже порога
```

## Особенности источников, о которых стоит знать

* **Схемы порталов меняются без предупреждения.** Поля ищутся по спискам
  синонимов (английские ключи + ивритские подписи), поэтому переименование
  колонки обычно не ломает сбор. Если поле всё же пропало — значение будет
  пустым, а не ошибочным.
* **Числовые коды назначения и статуса** рм"י расшифровываются таблицей в
  `landtender/sources/rmi_michrazim.py`. Незнакомый код оставляет поле
  пустым; свои значения задаются через `purpose_codes` / `status_codes` в
  секции `[sources.rmi_michrazim]`.
* **Yad2 защищается от ботов.** Отказ этого источника не роняет запуск — он
  попадает в раздел «Источники с ошибкой». При необходимости в конфиг можно
  положить куки: `cookie = "env:YAD2_COOKIE"`.
* **Цены участков живут в деталях тендера**, а не в поиске. Детали
  догружаются только для новых и изменившихся тендеров (кеш отпечатков),
  лимит за запуск — `details_budget`.
